## 1. Project Overview

This project implements Othello (also known as Reversi), a strategy board game played on an 8 × 8 board. Players take turns placing counters on empty squares to outflank their opponent's counters. Outflanked counters are flipped to the current player's colour.

The project was developed in five stages, progressing from a command-line game to a browser-based game with an AI opponent, save/load functionality, logging, documentation and automated testing.

### Features

- Command-line gameplay using Python.
- Browser-based graphical interface using Flask, HTML, CSS and JavaScript.
- Validation of legal moves according to Othello rules.
- Automatic flipping of outflanked counters in all eight directions.
- AI opponent that evaluates legal moves and selects the highest-scoring move.
- Game state saving and loading using JSON.
- Display of current player, game status and final scores.
- Event and error logging.
- Automated tests using pytest.

## 4. Game Rules and Implementation

The game begins with four counters placed in the centre of the board in the standard Othello pattern. Dark plays first.

A move is legal only when:

1. The selected square is empty.
2. At least one opponent counter is positioned in a straight line from the selected square.
3. That line ends with a counter belonging to the current player, with at least one opponent counter between the two.

The game checks horizontal, vertical and diagonal directions. All opponent counters outflanked by a valid move are flipped.

If a player has no legal moves, their turn is passed. The game ends when neither player can move or the board is full. The winner is determined by counting the Dark and Light counters.

## 5. AI Opponent

The AI replaces the second human player in the completed game.

It uses a straightforward move-evaluation algorithm rather than a complex search algorithm.

The process is:

1. Identify every legal move available to the AI.
2. Evaluate each candidate move.
3. Calculate a score using the number of opponent counters that would be flipped and board-position advantages, such as occupying a corner.
4. Compare the scores of all legal moves.
5. Select the move with the highest score.
6. Apply the move and flip the outflanked counters.

This approach provides a simple, understandable opponent while demonstrating basic decision-making and heuristic evaluation.

The AI does not use minimax or search several turns into the future.

### AI flowchart

The AI decision-making process is illustrated in `flowchart(AI opponent).png`.

The flowchart follows this sequence:

**Start → Find legal moves → Are legal moves available? → Evaluate each move → Compare scores → Select highest-scoring move → Apply move → End**

If no legal move is available, the AI passes its turn.

## 6. Design Decisions

### Separating game logic from the interface

The game rules are kept in Python so they can be reused by both the command-line and web versions. This avoids duplicating the move-validation and piece-flipping logic.

### Using Flask

Flask provides a connection between the Python game engine and the browser. The browser sends requests when the user makes a move, and Flask processes those requests and returns the updated game state.

### Using JSON

JSON provides a simple, readable format for storing the board and current player. This allows a saved game to be restored without requiring a database.

### Using a heuristic AI

A heuristic makes decisions by assigning scores to possible moves. This approach is easier to implement and explain than more computationally expensive game-search algorithms.

### Using a logging module

Logging records relevant game events and errors, helping with debugging and identifying unexpected behaviour.

## 9. Saving and Loading

The web interface supports saving and loading a game using JSON.

- **Save Game:** Stores the current board and current player in `saved_game.json`.
- **Load Game:** Reads the saved JSON file and restores the game state.

The save file is generated when the save function is used. It is not necessary to include a previous gameplay session in the submission.

## 10. Flask API

The Flask server provides endpoints that allow a browser or another compatible interface to interact with the game.

### `GET /`

Returns the HTML page containing the game interface.

### `GET /get_board`

Returns the current board and current player in JSON format.

Example response:

```json
{
  "board": [
    ["None", "None", "None", "None", "None", "None", "None", "None"]
  ],
  "current_player": "Dark"
}
```

This is an abbreviated illustration of the board structure. The actual response contains all eight rows.

### `POST /make_move`

Accepts a move from the client.

Example request:

```json
{
  "row": 2,
  "col": 3
}
```

The row and column use zero-based indexing, so the top-left square is `(0, 0)`. The server validates the move, updates the board and returns the resulting state. An illegal move returns an error response.

### `POST /save`

Saves the current board and player to `saved_game.json`.

### `GET /load`

Loads the saved game and returns the restored board and current player. If no save file exists, the server returns an error response.

### Creating an alternative GUI

Another interface can communicate with the Flask server using HTTP requests. It can request the board using `GET /get_board`, submit moves using `POST /make_move`, and use the save and load endpoints.

The alternative interface must send the expected JSON fields and handle error responses. The Python server remains responsible for validating moves and updating the game state.
